# ChunkHP requirements

## Request and targets

- Source: user request, 2026-11-10: "when you see a health bar take damage, it chunks it off ... takes that chunk and like fades it out ... can we animate the incoming damage on the mob". Follow-up: "Yes, build it" (flash + trail design). 2026-11-10: "Continue the work on HitTrail".
- Target: **WoW Forever** only. Interface 16001, build 1.60.1. No Retail/Classic distributable.
- Source pin for API checks: Gethe/wow-ui-source `9dc84f0d3bbae1768ac3405b3716000bd93eda06` (Forever 1.60.1.70862), plus thott.bot (build 1.60.1.70888) for secret-value flags.

## Requirements

| ID | Requirement | Acceptance |
|---|---|---|
| REQ-001 | When the target takes damage, the lost slice of its health bar flashes and fades out. | Hit a mob: the slice between new and old health shows white and fades out over about `fadeTime`. Heals show nothing. |
| REQ-002 | Behind the flash, the lost slice lingers as a trail, then drains to the new health. | After about `delay` the orange slice eases down to the real fill. Repeated hits keep one trail that holds until the last hit's delay ends. |
| REQ-003 | The same effect works on nameplates. | Visible enemy and friendly nameplates show the effect where addons may touch them. Restricted plates (enemy plates in instances) are skipped without errors. |
| REQ-004 | It never does math on secret health values. | No "secret value" Lua errors during combat, target swaps, nameplates appearing and disappearing, or max-health changes. |
| REQ-005 | Options in the game's Options > AddOns menu. | A "ChunkHP" category lists checkboxes for target frame, nameplates, flash and trail, plus sliders for trail hold time (0–1.5 s) and flash fade time (0.1–1.5 s). Changes apply immediately and persist through /reload and relog. |
| REQ-006 | Slash command supplements the menu. | `/chunkhp` prints help and state, `target`/`nameplates`/`flash`/`trail` toggle, `delay <s>`/`fade <s>` set times, and `options` opens the menu page. |
| REQ-007 | Localization. | All addon-owned text comes from `Locales/Base.lua` (English fallback). No other locales are shipped yet. |
| REQ-009 | Preview in the options page so users can try the timing (user, 2026-11-10: "inside the options can we put a little \"simulator\" to test the timing"). | The top of the ChunkHP page shows a fake health bar with Hit, Big hit, Heal and Auto buttons. It uses the same flash/trail code and the current settings: toggles apply right away, and slider changes affect the next hit. Auto stops when the page closes. |
| REQ-010 | Style presets that "feel" like other games (user, 2026-11-10: "i want to have some presets that \"feel\" like other games like final fantasy online"; approved "Yes, build presets"). | A "Style" dropdown at the top of the options page offers Classic MMO, Soulslike, Fighting Game, JRPG, Arcade and Custom. A number-size slider appears only if the client has `WorldTextScale_v2` or `WorldTextScale`. A "Restore defaults" button resets them to the game's defaults. ## Decisions

- DEC-001: Overlay bars sit in a frame that clips to the empty part of the Blizzard bar. Health values only ever go into `SetValue`/`SetMinMaxValues` (secret-safe).
- DEC-002: The options page uses the stock vertical Settings layout. The user chose "Implement directly" (no mock-up) on 2026-11-10.
- DEC-004: The preview is a custom row (`ChunkHPPreviewTemplate`, built with `Settings.CreateElementInitializer` and `Settings.RegisterInitializer`, both verified at the Forever pin) inside the stock vertical layout, not a canvas page. It reuses the existing "Implement directly" choice.
- DEC-005: Presets are named by genre, not by game (trademark safety). Research found no source that FFXIV's own bars do this, so there is no "FFXIV" preset. The drain speed can't vary per preset because the trail must use Blizzard's ExponentialEaseOut with secret values. Presets vary flash on/off, flash fade time, hold time, trail on/off and the two colors.
- DEC-006: The addon name stays "ChunkHP" for now. The user saw alternatives (Afterimage, GhostBar, Zanzo, ChipDamage, Lingerbar, HealthEcho) and chose to build presets first.
- DEC-007: The preview copies the nameplate look instead of reusing Blizzard's `NamePlatePreviewTemplate`. That template registers the single "preview" nameplate token and shows the player's real health, so it can't play fake hits, and two copies would fight over the token. The art, sizes and offsets come from Blizzard_NamePlates and Blizzard_SettingsDefinitions_Frame at the Forever pin (`9dc84f0`): atlases `UI-HUD-CoolDownManager-Bar`, `-Bar-BG`, `-Selected-yellow` and `options_frame_child`; classic `UI-TargetingFrame-BarFill` + `Nameplate-Border`; width 190 (classic 128), height 13/20 (classic 10), scaled by `NAME_PLATE_SCALES`.
- DEC-008: The preview reads its sizes from the live `NamePlateSetupOptions` and `NamePlateDriverFrame:GetNamePlateWidth/GetNamePlateScale`, the same values real plates use: side inset, bar height, level box width, name anchoring and spacing. Constants are only the fallback. The level box copies `NameplateLevelFrame` (Camelot): atlas `ui-hud-nameplates-levelindicator`, its selected rectangle, font `SystemFont_NamePlateLevel`, and a 5px gap from the bar.
- DEC-009: The damage-number controls are proxy settings over the game's own options. The on-target CVar names are confirmed in Forever's CombatOverrides.lua at the pin. The size CVar isn't in Forever's options code, so it's checked at runtime and hidden if missing. Out of scope because the engine draws the numbers and the amounts are secret to addons (`C_CombatText.GetCurrentEventInfo` returns secrets, and the combat log is restricted): color, animation, crit styling and custom-drawn numbers. The font (`DAMAGE_TEXT_FONT`) was declined by the user.
- DEC-010: Renamed from HitTrail on 2026-11-10. The old folder couldn't be renamed in place while the session held it, so it was copied to `ChunkHP/` and the old folder removed. The saved settings were migrated by writing `WTF/Account/<account>/SavedVariables/ChunkHP.lua` (`ChunkHPDB`, copied from `HitTrailDB`). The old `HitTrail.lua` saved-variables file was left in place. Releases are built as `AddOns/ChunkHP-<version>.zip` without `docs/`.
- DEC-011: Releases are automated with GitHub Actions and BigWigsMods/packager@v2 (v2.6+ supports Forever and detects interface 16001 as Forever). Pushing a `v*` tag builds the zip per `.pkgmeta` and creates a GitHub release. The CurseForge upload starts once `## X-Curse-Project-ID` is in the TOC and the repo has a `CF_API_KEY` secret. `## Version` in the TOC stays manual and must match the tag.
- DEC-003: Bar colors stay saved-variable only (`flashColor`, `trailColor`) and are not shown in the menu yet.
